Esta sesión

Vamos a pasar de prompts aislados a un sistema que sostiene contexto, sigue un método y ayuda a entregar trabajo útil.

Código agéntico

Es la evolución del vibe coding.

El agente puede ayudar con código y DevOps. Solo será seguro y útil si recibe buen contexto, límites claros y una forma de verificar el resultado.

Contexto

Qué proyecto es, qué importa y qué no se debe tocar.

Tarea

Un resultado concreto, con herramientas y límites definidos.

Prueba

Un artefacto, una verificación y la siguiente decisión humana.

Harness engineering

El harness dirige al agente.

  1. ContextoSolo lo necesario para esta tarea.
  2. MemoriaHechos y preferencias estables.
  3. SkillsMétodos repetibles y verificables.
  4. HerramientasCapacidades para actuar en el mundo real.
  5. CicloInspeccionar, actuar, probar y reportar.

Un mejor modelo no rescata un flujo de trabajo vago.

Instala

Configura

Un perfil, una ruta de modelo, contexto del proyecto y permisos adecuados.

Conecta y prueba

Conecta Telegram como superficie privada opcional. Revisa las tools instaladas y completa una tarea pequeña.

Desplegar no es solo poner un agente en un servidor. Es darle un lugar para correr, una configuración mínima, una superficie de comunicación y evidencia de que sus tools funcionan.

Estructura inicial

Resource Inbox empieza con un post público.

título contenido URL estrellas de recomendación de IA: 0.0 a 5.0 votos positivos / negativos
Sin complejidad extra

Sin autenticación, comentarios ni moderación compleja en la primera versión.

Arquitectura primero

Sitio web en Render conectado a un backend en Convex.

Funcionalidad

Envía un recurso. Evalúalo. Publícalo.

título + contenido + URL ↓ Convex guarda el post ↓ el LLM asigna 0.0 a 5.0 estrellas ↓ el usuario confirma la calificación ↓ Render muestra el post en el feed público
Interacción pública

Las personas pueden votar positivo o negativo. El objetivo es mostrar persistencia, no construir un sistema de votos listo para producción.

Límite del agente

El LLM da una recomendación. La persona decide si la confirma.

Despliegue

Primero la arquitectura. Después, lo construimos en vivo.

Render

Sitio web público.

Convex

Posts, persistencia y estado de votos.

LLM

Calificación de recomendación acotada.

  • Crear un post
  • Ver la calificación del LLM
  • Confirmar o ajustar la calificación
  • Publicarlo en el feed
  • Votar positivo o negativo
  • Recargar y confirmar persistencia

Intentaremos construir este flujo en vivo. Si un servicio bloquea el camino, volvemos a la arquitectura y al artefacto local.
